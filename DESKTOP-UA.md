# Fleng: запуск додатка разом із локальним сервером

Інтеграція у `fleng-fly` — 2026-11-14: вихідні файли та переносний runtime
перенесені. На Windows пройшли п’ять перевірок сервера й збереження даних;
саме вікно браузера не запускалося. Нижче також збережено історичні результати
попередньої збірки. Актуальні перевірки: `docs/projectenglich-integration.md`.

## Windows 10/11 x64 — готовий переносний пакет

1. Повністю розпакуй ZIP у звичайну папку, наприклад «Документи/Fleng».
2. Двічі натисни **Fleng.exe**. Поряд мають залишатися папки runtime,
   desktop, backend і frontend. Не запускай EXE безпосередньо всередині ZIP.
3. Дочекайся вікна входу. Fleng сам готує локальну базу і запускає свій сервер.
4. Закрий вікно Fleng — його сервер завершиться автоматично.

Python і Node.js для переносного Windows-пакета встановлювати не потрібно.
Потрібен установлений **Microsoft Edge або Google Chrome**. Fleng відкриває
окреме вікно браузера у режимі додатка, без звичайного рядка адреси.
Окремий WebView2 Runtime та pythonnet для Windows-запуску більше не потрібні.

Fleng.exe — невеликий нативний Windows-запускач; Python та залежності лежать
у runtime. Пакет не має інсталятора і не реєструє системної служби чи автозапуску
разом із Windows. Збірка не має цифрового підпису видавця.

## Як це працює

Вікно Fleng → власний локальний FastAPI → міграції SQLite → перевірка готовності
→ вхід/навчання. Сервер слухає **тільки 127.0.0.1** на вільному порту.
Доступ із зовнішньої мережі та довіра до proxy-заголовків не вмикаються.
Node.js, npm, PostgreSQL, IIS і ручний запуск uvicorn не потрібні.

Повторний запуск повідомить, що Fleng уже відкрито. Закриття вікна коректно
завершує лише свій процес сервера. Якщо вікно аварійно завершується, сервер
бачить закриття службового каналу й теж завершується. Інші сервери й програми
не зупиняються.

## Де зберігаються облікові записи й прогрес

- Windows: `%LOCALAPPDATA%/Fleng/`.
- Linux: `$XDG_DATA_HOME/Fleng/` або `~/.local/share/Fleng/`.

Там розміщено fleng.db, локальний ключ jwt-secret.txt, окремий профіль браузера
і журнали desktop.log, backend.log та browser.log. Повторний запуск та розпакування нової версії не видаляють дані.
Не видаляй цю папку, якщо хочеш зберегти облікові записи й прогрес.

Якщо це перехід із локальної вихідної версії і в `backend/data/fleng.db` уже є
база, перший запуск копіює її через SQLite backup API. Старий файл не змінюється,
а вже наявна настільна база не перезаписується. Знадобиться знову увійти.
Якщо ти переніс стару базу в інше місце, не підміняй файли під час роботи Fleng:
спочатку закрий додаток і збережи резервну копію.

**Локальна база окрема від онлайн-сайту.** Облікові записи й прогрес з хостингу
автоматично сюди не синхронізуються. На іншому комп'ютері буде власна локальна база.
Основне локальне навчання працює без зовнішнього сервера; AI та SMTP залежать
від інтернету й налаштованих сервісів.

## Linux та запуск із вихідного коду

У переносному Windows-архіві також є всі вихідні файли. Linux не запускає Fleng.exe.
На Linux із Python 3.11+ запусти `sh START-FLENG.sh`.
Під час першого запуску створюється `.desktop-venv`, встановлюються бекенд
і pywebview[qt]; потрібен інтернет. Далі відкривається те саме окреме вікно.
Системні бібліотеки Qt залежать від дистрибутива; це не готовий AppImage.

Для вихідної версії на Windows із установленим Python можна запускати
`START-FLENG.cmd`. Це окремий режим із початковим установленням залежностей,
а не Fleng.exe з готового пакета.

## Android та iPhone

Вебдодаток PWA, який раніше встановлювався через `/install.html`, не може
самостійно запустити Python-сервер на телефоні або увімкнути вимкнений комп'ютер.
На телефоні потрібен доступний онлайн-сервер; після його закриття на комп'ютері
мобільна PWA не отримує API. APK/IPA з локальним Python-бекендом тут не створено.
Для спільного облікового запису на кількох пристроях потрібно розгорнути
постійно доступний сервер і використовувати онлайн-версію.

## Якщо запуск не вдався

- Повністю розпакуй архів; зберігай Fleng.exe разом з усіма його папками.
- Перевір установлення Edge або Chrome на Windows. Пакет призначено для x64.
- Перевір backend.log у папці даних. Якщо помилка підготовки бази, не видаляй
  базу й не позначай міграції вручну: збережи журнал і резервну копію.
- Якщо Fleng уже відкрито, перемкнись до його вікна.
- Після помилки GUI запускач завершує свій сервер; повторний запуск безпечний.

## Що перевірено

Фактичний запуск локального FastAPI, міграції, реєстрація, вхід, збереження
облікового запису після перезапуску, завершення сервера, завершення при аварії
батьківського процесу, блокування другого запуску та копіювання старої бази
перевіряються тестами desktop/tests на Linux.

Windows-пакет зібрано з офіційного Python 3.14.10 x64, його SHA-256 перевірено
за python.org. Залежності — Windows wheels, запускач — PE x64 із GUI subsystem.
Версії й контрольні суми є у BUILD-MANIFEST.json та WINDOWS-DEPENDENCIES.txt.
Вікно Edge/Chrome та запуск Windows EXE на реальній Windows у цьому середовищі
**не перевірялися**. Перевірка процесу сервера на Linux не замінює такої перевірки.

## Для розробника

- `desktop/main.py`: запуск Windows через Edge/Chrome, Linux через pywebview.
- `desktop/chromium.py`: власний профіль браузера та контроль закриття вікна.
- `desktop/diagnostics.py`: перевірка середовища без читання облікових записів.
- `desktop/runtime.py`: папка даних, OS lock, запуск/готовність/зупинка процесу.
- `desktop/worker.py`: існуючий FastAPI на loopback, EOF завершує сервер.
- `desktop/launcher.c`: нативний Windows-запускач bundled pythonw.exe.
- `desktop/build_windows.py`: збірка папки з перевіреного embeddable runtime
  та wheelhouse; вихідні файли бере тільки з Git HEAD.

Для відтворення збірки потрібні Python із ziglang, офіційний
python-3.14.10-embed-amd64.zip та wheelhouse з переліку WINDOWS-DEPENDENCIES.txt.
Для proxy_tools 0.1.0, який постачається як вихідний пакет, спочатку створюється
універсальний wheel без платформних розширень. Для інших залежностей потрібні
Windows x64 wheels CPython 3.14 або сумісні abi3/pure-Python wheels.
При cross-platform download явно додати pythonnet, clr_loader, cffi та colorama:
умовні залежності не можна вважати автоматично правильно вибраними за --platform.
uvicorn у переносному пакеті використовується без extras standard: HTTP і SSE
працюють на стандартному asyncio, uvloop для Windows не потрібен.

Приклад після підготовки входів і коміту змін:
`python desktop/build_windows.py --runtime <python.zip> --wheels <wheelhouse> --output <new-folder>`

Результат поточної перевірки: 5 lifecycle/даних тестів настільного режиму,
58 регресійних тестів UI/API/автентифікації/вправ/прогресу пройдено.
Ruff, mypy для існуючого backend і git diff --check пройдено.
Окремий self-review виправив закриття SQLite backup-з'єднань перед перейменуванням
файлу на Windows; повторна перевірка настільних тестів пройшла.
Для build_windows.py потрібен також пакет packaging: він перевіряє граф
залежностей саме для Windows і Python 3.14, незалежно від платформи збірки.


## Виправлення Windows-запуску — 2026-11-14

Попереднє загальне повідомлення про WebView2 не відображало справжню помилку.
За скріншотом точну причину не встановлено. Windows-запуск тепер обходить
вбудований pywebview/.NET/WebView2 шлях і використовує наявний Edge або Chrome
у режимі додатка. Сервер запускається автоматично до відкриття вікна.

Використовується власний профіль `%LOCALAPPDATA%/Fleng/browser-profile`.
Звичайний профіль і відкриті вкладки твого браузера не використовуються.
DevTools увімкнено лише на loopback і вільному порту цього приватного профілю,
щоб визначати закриття вікна. Після закриття сторінок Fleng сервер завершується
приблизно за 2 секунди. Переходи між уроками й входом його не зупиняють.
При політиці Windows/браузера, що забороняє remote debugging, запуск може
не підтвердитися; програма покаже помилку і запише desktop.log.

Для додаткової перевірки відкрий CHECK-FLENG.cmd — він покаже знайдений браузер
та імпорт основних залежностей. Журнал вікна: `%LOCALAPPDATA%/Fleng/desktop.log`;
журнал сервера: `%LOCALAPPDATA%/Fleng/backend.log`.

У малому архіві виправлення достатньо скопіювати файли у стару папку програми
зі злиттям папки desktop та заміною main.py. Fleng.exe і runtime не замінюються.
База даних і локальний ключ не змінюються. Після переходу до нового профілю
браузера може знадобитися повторний вхід із наявним локальним обліковим записом.

Перевірено 10 тестів: lifecycle, збереження бази, пошук браузера, читання порту,
відстеження власної сторінки після завершення стартового процесу браузера,
перехід dashboard/login, виявлення закриття та запуск Windows без імпорту
модуля webview. Саме вікно Windows на цьому комп'ютері не запускалося.
