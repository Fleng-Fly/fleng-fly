# Documentation guidelines

Use English/GitHub Markdown, relative links and source-derived examples. Distinguish implemented/draft/experimental/planned/unverified. Structural success is not linguistic approval; offline SQL is not live PostgreSQL.

Numbered sections provide current navigation. Retained documents preserve detailed operations/history; [preservation register](../12-reference/documentation-migration.md) maps them and caveats. Avoid full duplicated report copies.

Update API/config/model references with code changes. Run documentation links/contracts and diff checks. Synthetic examples must never contain real secrets. Keep dated test counts in reports, not permanent capability claims.
