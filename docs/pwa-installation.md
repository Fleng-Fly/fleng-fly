# Встановлення Fleng на чотирьох платформах

Fleng тепер має PWA: `frontend/manifest.webmanifest`, спільний `js/pwa.js`,
кореневий `sw.js`, PNG-іконки й загальнодоступну сторінку `/install.html`.
Стек залишається HTML/CSS/JavaScript + FastAPI без збірки фронтенду.

## Встановлення

- Windows: Edge або Chrome → «Встановити Fleng» чи встановлення через меню браузера.
- Linux: Chrome або Chromium із підтримкою PWA → встановлення через меню браузера.
- Android: Chrome → «Встановити додаток»; альтернативно меню додавання на головний екран.
- iPhone: Safari → «Поширити» → «На початковий екран» → «Додати».
  Якщо є перемикач «Відкривати як вебпрограму», увімкнути його.

Кнопка показується лише після справжнього `beforeinstallprompt`; без цієї події
залишаються ручні інструкції. Скасування діалогу не показує хибний успіх.
У встановленому вікні пропозиція встановлення прихована.

## Розгортання

Розгорнути **весь оновлений проєкт** на чинному сервері за наявною процедурою
`docs/deployment.md`. FastAPI обслуговує UI та `/api/v1` з одного HTTPS-домену.
Після розгортання відкрити `https://<домен>/install.html` на кожному пристрої.
Не роздавати лише `frontend/` з іншого домену без проксі до API.
Доступ до наявного хостингу й публікацію в цій зміні не виконано.

Для локальної перевірки: `npm run dev`, потім
`http://localhost:3001/install.html`. На Windows є `START-WINDOWS.cmd`.
На Linux потрібні Python 3.11+, пакет venv для Python та Node.js 20+.
Телефон не може використати localhost комп’ютера; HTTP-адреса локальної мережі
не замінює HTTPS для PWA. Потрібен доступний HTTPS-сервер.

## Дані та робота без мережі

Встановлений Fleng відкриває `/dashboard.html` через існуючий захист сесії.
Облікові записи й прогрес залишаються у серверній базі; потрібен той самий сервер
і вхід у той самий обліковий запис. Ізоляція cookies між браузером і встановленим
додатком залежить від платформи: може знадобитися повторний вхід.

Service worker кешує **тільки самодостатню публічну `/offline.html`**.
HTML користувача, API, токени, відповіді, XP, чат і прогрес не кешуються.
Навігація завжди йде у мережу; лише мережевий збій повертає offline-екран.
Запити `/api/*`, записи й міждоменні запити worker не перехоплює.
Ненадіслані відповіді не ставляться у фонову чергу. Офлайн-уроки не реалізовані.

Це PWA, а не зібрані EXE/AppImage/APK/IPA, і не публікація в App Store/Google Play.
Оновлення надходять із того самого сервера при відкритті онлайн.
Для зміни offline-екрана підняти суфікс `fleng-offline-v1` у `sw.js`;
активація видаляє тільки попередні кеші з префіксом `fleng-offline-`.

## Перевірки

- `node scripts/test-pwa.mjs` — відсутність перехоплення API/POST/сторонніх
  запитів, live HTML, offline fallback та ізоляція кешів.
- `pytest tests/test_frontend.py tests/test_pwa.py` — реальна роздача сторінок,
  маніфесту, PNG, worker та збереження API error envelope.
- `node scripts/test-pwa-install.mjs` — кнопка за наявності браузерної події,
  скасування, installed/standalone, HTTPS та збій реєстрації worker.
- Chromium QA не виконано: середовище забороняє створення потрібного браузеру
  системного socket (Operation not permitted). Верстка 390/1440 px, справжній
  діалог встановлення та manifest installability потребують браузерної перевірки.
- Фізичні Windows/Android/iPhone, Safari та системне встановлення Linux тут
  не перевірялися; інструкції ґрунтуються на документації нижче.

Джерела: https://web.dev/learn/pwa/installation,
https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable,
https://support.apple.com/guide/iphone/iphea86e5236/ios.
